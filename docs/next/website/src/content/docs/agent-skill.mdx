Herdr ships a reusable, harness-neutral skill folder at [`skills/herdr/`](https://github.com/f5-sales-demo/herdr/tree/build-xcsh/skills/herdr).

Install the whole folder when your coding agent supports skills. Its concise `SKILL.md` contains the independently useful core, while `references/` progressively supplies advanced agent, automation, external-worker, remote, and persistence guidance.

Herdr also serves a separate guide at [`herdr.dev/agent-guide.md`](https://herdr.dev/agent-guide.md) for a different job: an agent helping a human learn, set up, or troubleshoot Herdr. The skill is for an agent operating Herdr; the guide is for an agent teaching a human.

## What the skill does

The skill authorizes control in two explicit contexts:

- an agent running in a Herdr-managed pane with `HERDR_ENV=1`;
- an external worker whose launcher was explicitly paired to a selected pane and resolves a renewable lease for each launch.

An unpaired process must not search for sockets, inject `HERDR_ENV`, or infer ownership from its working directory. The absence of `HERDR_ENV` in an isolated worker does not prove that the human has no Herdr session.

With the skill installed, an agent can inspect and operate Herdr topology, run and observe commands, coordinate recognized agents, target saved machines safely, and use capability-gated durable execution or interaction contracts.

The skill is Markdown instructions, not an application or service. If Herdr is already installed, `herdr --skill` prints the release-matched self-contained core bundled with that binary. A single-file command cannot include the folder's optional reference files; install the repository folder for progressive disclosure.

## Install it

Install the skill folder with `npx skills`:

```bash
npx skills add f5-sales-demo/herdr --skill herdr -g
```

If you installed the skill while it lived at the repository root, rerun this add command once instead of using `skills update`. The add command replaces the oversized copy and records the canonical folder location.

The `-g` flag installs it globally for supported agents. Omit `-g` to install it into the current project.

Use the canonical repository folder as the manual source of truth:

```text
https://github.com/f5-sales-demo/herdr/tree/build-xcsh/skills/herdr
```

For another harness with a compatible skill system, install that folder as a skill named `herdr`. For a harness that accepts only one custom-instructions file, use `SKILL.md`; its core remains complete without the optional references.

After installation, start the agent inside Herdr:

```bash
herdr
<your-agent-command>
```

The installed binary's `agent` and `integration` discovery commands determine supported kinds and behavior. Codex, Claude Code, OpenCode, and xcsh are examples, not assumptions.

## Safety rule

The skill requires either inherited managed-pane context or explicit external-worker pairing. If neither exists, the agent stops live control without claiming that the user's Herdr session is absent.

The skill also keeps focus, ownership, opaque ID, destructive-operation, update-consent, capability-negotiation, and private-answer boundaries in the root file so they remain present in `herdr --skill` output.
