---
title: 追跡可能なコマンド実行
description: 自動化クライアント向けにサーバーが管理するコマンドのライフサイクル。
---

追跡可能な実行は、端末の文字列やエージェントの画面状態を解釈せずに、プロセスのライフサイクルを確認するための証拠を提供します。

## 契約

`execution.start` には、呼び出し元が生成した `execution_id`、存在する絶対パスの `cwd`、および次のいずれかのコマンド形式が必要です。

- `{"mode":"argv","argv":[...]}` は引数配列を直接実行します。
- `{"mode":"shell","shell":"bash|zsh","text":"..."}` は指定したシェルの `-lc` の動作で文字列を実行します。

受け付けた実行ごとに、指定されたワークスペース（省略時はアクティブなワークスペース）に新しいタブが作られます。タブにはフォーカスを移しません。ルートペインは Herdr のネイティブ PTY でコマンドを直接起動します。出力を確認でき、xcsh のような対話型ツールには通常どおり `pane.send_text`、`pane.send_keys`、端末への接続を利用できます。

同じ ID と同じ設定で開始要求を繰り返すと、既存の記録が `admitted: false` とともに返り、別のタブは作られません。異なる設定で ID を再利用すると `execution_id_conflict` になります。サーバーは受付、PTY の起動成功、タブとペインの ID、PID、観測した終了コードまたはシグナル名、キャンセル要求、バイト数、および PTY ストリームを編集した最大 4 KiB の末尾を記録します。PTY では stdout と stderr を確実に区別できないため、`stdout_tail` は結合されたストリームを表し、`stderr_tail` は空です。プロセスの終了と PTY 出力の読み切りは別の事実です。`output_complete: true` は、ネイティブリーダーが残りのバイトを読んだ後に EOF に達したことを意味します。

完全な記録は Herdr の名前付きセッションごとに 256 件まで保持します。期限切れの ID は、最近の 4,096 件のトゥームストーンと永続的な 64 Kibit の確率的フィルターで保護します。このフィルターは、そのバイナリが登録した ID に対して偽陰性を生じないため、期限切れの ID が黙って再実行されることはありません。偽陽性の場合は安全側に倒して `execution_expired` を返すので、新しい ID を使ってください。

`execution.get`、`execution.list`、`execution.wait` を使って状態を照会し、リビジョンをロングポーリングし、再接続後の変更を再生します。保持されているセッションジャーナル内ではリビジョンが単調増加します。コンシューマーは観測した最大のリビジョンを保存し、重複記録を許容し、同じ ID の後続の記録を正としてください。

`execution.cancel` は Herdr が所有する PTY の子プロセスハンドルから複製した終了手段を使います。キャンセル応答の成功が証明するのは終了要求だけです。同じ子プロセスの監視処理が待機結果を伴う `cancelled` または `exited` を報告して初めて、終端状態が確定します。

## 復旧と意味上の制限

記録はペインとは独立して永続化されます。コマンドの開始中または実行中に Herdr サーバーが再起動した場合、復元された記録は `evidence_gap` を伴う `lost` になります。Herdr は子プロセスが生存、終了、または正常終了したとは主張しません。これは重複を抑止する少なくとも 1 回の受付であり、分散システム全体での厳密な 1 回実行ではありません。

追跡可能な実行は、フォーカスを奪わない対話型 PTY ペインに表示されます。シェルプロンプト、端末の内容、または TUI がアイドルに見えることは終了の証拠ではありません。Codex や xcsh のプロセスが正常終了しても、依頼したタスクの成功は証明されません。エージェント固有の意味的ライフサイクルを別途確認してください。

## ネイティブの意味的ターン

プロトコル 22 では、サーバーが永続的なネイティブの意味的結果をサポートする場合、`agent_turn_journal` を広告します。追跡対象のエージェントは `HERDR_EXECUTION_ID` を受け取り、その実行 ID とサーバーが割り当てた `HERDR_PANE_ID` の両方に対して報告します。ペインが実行の所有下にない場合、Herdr は報告を拒否します。

JSON API では `agent.turn.report`、`agent.turn.get`、`agent.turn.list`、`agent.turn.wait` を使います。ターンはプロデューサー、ネイティブセッション ID、ネイティブターン ID、世代で識別されます。プロデューサーの `event_revision` は 1 から始まり単調増加します。Herdr はコンシューマー向けに別のジャーナル `revision` を割り当てます。同一の報告は冪等です。同じリビジョンで内容が変わった報告、古いリビジョン、終端イベント後の更新は拒否されます。

状態は `starting`、`working`、`waiting_input`、`completed`、`failed`、`cancelled`、`interrupted`、`lost` です。最初のイベントは `starting` でなければなりません。結果を持てるのは `completed` だけで、結果は UTF-8 で最大 8,000 バイト、SHA-256 ダイジェスト付きです。理由も最大 8,000 バイトです。サーバー再起動時には、終端していない最新のターンはそれぞれ `lost` になり、終端済みの記録は永続ジャーナルから再生されます。保持件数には上限があるため、コンシューマーは Herdr を無期限の結果保存先とみなさず、受理したイベントとリビジョンを保存してください。

意味的な完了は実行の終了や出力の読み切りとは独立しています。マネージャーは、受け付けた実行と期待するネイティブ ID に一致する終端の意味的イベントだけをタスク成功として受理します。`execution.state`、ペイン状態、端末出力、メタデータトークンから成功を推測しないでください。

## CLI

```sh
herdr execution start build-42 --cwd /srv/project -- just check
herdr execution start script-42 --cwd /srv/project --shell zsh -- 'printf "%s\n" "$PWD"'
herdr execution get build-42
herdr execution list --since 120
herdr execution wait 120
herdr execution cancel build-42
```

API ソケットには所有者のみがアクセスできます。出力の末尾は一般的な認証情報ラベルについて可能な範囲で編集されますが、呼び出し元は秘密情報や機密の完全なトランスクリプトを表示してはいけません。ブローカー移行では旧方式を完全に置き換えます。受付前に実行 ID を生成して保存し、制御用ワークスペースと安全なタブラベルを指定して `execution.start` を呼び、返されたタブとペインの ID を表示と対話入力用に保持し、`get`、`list --since`、`wait` で照合します。ネイティブバイナリが展開され、ブローカーが再接続とキャンセルの UAT に合格してから、Python ラッパーのコールバック、スプールファイル、プロンプトのスクレイピング、ペイン ID による完了推測を削除してください。
